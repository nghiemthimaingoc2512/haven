# 16 - Roadmap

Phased by what has to be proven before the next layer makes sense - not by arbitrary quarters. See [19-mvp.md](19-mvp.md) for the detailed MVP spec and [07-user-research.md](07-user-research.md) for the research gates each phase depends on.

## Phase 0 - Prove the magic moment (pre-launch)

**Goal:** validate that an accurate, memory-informed reflection actually lands the way the seed concept describes, before building anything else around it.
- Research Phases 1–2 from [07-user-research.md](07-user-research.md).
- A minimal prototype: text-only, single-session listening + reflection, no persistent memory yet.
- Kill criterion: if reflection reads as uncanny, generic, or performative to test users more often than it lands, we stop and rework the core interaction before writing another feature.

## Phase 1 - MVP: listening + short-term memory + safety (see [19-mvp.md](19-mvp.md))

**Goal:** a small closed beta can have a real, ongoing relationship with Haven across weeks, safely.
- Core listening modes, end-of-session reflection ritual.
- Memory within and across a limited recent window (not yet the full long-term architecture).
- Crisis detection and handoff - non-negotiable, ships with this phase, not after.
- Full memory/data controls (view, delete, export) - non-negotiable, same reasoning.
- No monetization yet. Closed beta, invitation-based, small enough to review conversations for safety failures by hand.

## Phase 2 - Long-term emotional memory + pattern surfacing

**Goal:** deliver the actual differentiator - memory that compounds over months, not weeks.
- Structured, persistent memory architecture (themes, people, recurring feelings) as specified in [11-product-prd.md](11-product-prd.md) §2.
- Pattern surfacing and "remind me who I was" recall.
- Public launch with the subscription model from [17-business-model.md](17-business-model.md) - we do not monetize before the memory differentiator exists, because charging for a product that's functionally a worse ChatGPT would undercut the entire positioning.

## Phase 3 - Voice and the therapist bridge

**Goal:** remove remaining access friction and strengthen the off-ramp principle.
- Voice mode, with the data-handling questions from [11-product-prd.md](11-product-prd.md) §7 resolved before launch, not during.
- Therapist bridge: consent-gated theme summaries a person can bring to a real first session.

## Phase 4 - Ritual and long-view features

**Goal:** make the multi-year value of accumulated memory tangible, not just theoretically present.
- Opt-in anniversary/milestone reflections (Stage 6 in [09-user-journey.md](09-user-journey.md)).
- Life-transition modes (grief, breakup, career change) informed by usage patterns and research from Phase 1–2 beta data.

## Explicit non-goals for the roadmap's first two years

Social features, gamification, an avatar/persona system, and advertising do not appear anywhere on this roadmap - not deprioritized, excluded. Revisiting any of them would require revisiting the mission itself, not just a backlog re-prioritization.
